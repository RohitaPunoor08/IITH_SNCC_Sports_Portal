# **IIT Hyderabad \- SNCC Multi-Sport Recreation Portal**

**Website**  
Link:- [https://iith-sncc-sports-portal.vercel.app/](https://iith-sncc-sports-portal.vercel.app/)

A real-time, multi-user web application designed to track facility availability, manage live waiting queues, and handle on-site court access at the Student Activity Center (SNCC) at IIT Hyderabad.

## **Key Features**

* **Real-time Status Tracking**: Monitor availability across 7 sports and 18 facilities in real time:  
  * Badminton (4 Courts)  
  * Table Tennis (4 Tables)  
  * Basketball (2 Courts)  
  * Volleyball (2 Courts)  
  * Carrom (3 Tables)  
  * Chess (3 Tables)  
  * Foosball (1 Table)  
* **Live Multi-Device Synchronization**: Built on Supabase Realtime (WebSockets) to ensure state changes on one device reflect instantly across all connected browsers.  
* **GPS Geofencing Verification**: Uses the browser's Geolocation API to verify physical presence within a **300-meter radius** of the SNCC Sports Complex (17.5947° N, 78.1230° E) before allowing court claims and dispute actions.  
* **Student Queue System**:  
  * Join waiting queues per sport and facility/court.  
  * Auto-saving student credentials (Name and Roll Number) via `localStorage`.  
  * Dedicated active queue status banner with one-click "Leave Queue" functionality.  
* **Staff Portal**:  
  * PIN/ID-authenticated control panel.  
  * Status options: `EMPTY`, `FULL`, `MAINTENANCE`, `OFFICIAL MATCH`, `NSO Practice`, and `Inter-IIT Practice`.  
  * **"Admit Next Student"** feature to automatically dequeue the next waiting student and mark the facility as occupied.  
* **Official IITH Branding**: Styled using official IIT Hyderabad color tokens (`Navy`, `Red`, `Orange`, and `Yellow`).

## **Tech Stack**

* **Frontend**: HTML5, CSS3, Vanilla JavaScript (ES6+)  
* **Database & Backend**: [Supabase](https://supabase.com/?utm_source=gemini) (PostgreSQL & Realtime WebSockets)  
* **SDK**: Supabase JS SDK v2 (`@supabase/supabase-js`)  
* **APIs**: HTML5 Geolocation API

## **Database Setup (SQL Schema)**

Run the following SQL script inside the **Supabase SQL Editor** to construct the required database schema, disable RLS for direct client operations, and enable real-time replication:

\-- 1\. Create Facilities Table  
CREATE TABLE IF NOT EXISTS sports\_facilities (  
    id TEXT PRIMARY KEY,  
    sport\_name TEXT NOT NULL,  
    court\_no INT NOT NULL,  
    availability TEXT DEFAULT 'EMPTY',  
    current\_player TEXT,  
    occupied\_since BIGINT,  
    updated\_at BIGINT DEFAULT extract(epoch from now()) \* 1000  
);

\-- 2\. Create Queue Table  
CREATE TABLE IF NOT EXISTS court\_queue (  
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,  
    student\_name TEXT NOT NULL,  
    roll\_no TEXT NOT NULL,  
    sport\_name TEXT NOT NULL,  
    court\_no INT NOT NULL,  
    created\_at TIMESTAMPTZ DEFAULT NOW()  
);

\-- 3\. Disable Row Level Security (RLS) for Direct Client Access  
ALTER TABLE sports\_facilities DISABLE ROW LEVEL SECURITY;  
ALTER TABLE court\_queue DISABLE ROW LEVEL SECURITY;

\-- 4\. Set Replica Identity for Realtime Subscriptions  
ALTER TABLE sports\_facilities REPLICA IDENTITY FULL;  
ALTER TABLE court\_queue REPLICA IDENTITY FULL;

\-- 5\. Enable Realtime Publications  
DO \$\$  
BEGIN  
    IF NOT EXISTS (  
        SELECT 1 FROM pg\_publication\_rel   
        WHERE prpubid \= (SELECT oid FROM pg\_publication WHERE pubname \= 'supabase\_realtime')  
        AND prrelid \= 'sports\_facilities'::regclass  
    ) THEN  
        ALTER PUBLICATION supabase\_realtime ADD TABLE sports\_facilities;  
    END IF;

    IF NOT EXISTS (  
        SELECT 1 FROM pg\_publication\_rel   
        WHERE prpubid \= (SELECT oid FROM pg\_publication WHERE pubname \= 'supabase\_realtime')  
        AND prrelid \= 'court\_queue'::regclass  
    ) THEN  
        ALTER PUBLICATION supabase\_realtime ADD TABLE court\_queue;  
    END IF;  
END \$\$;

\-- 6\. Reload Schema Cache  
NOTIFY pgrst, 'reload schema';

## **Geofencing & Location Verification**

The portal uses the Haversine Formula to compute distance against the fixed location of the SNCC Sports Complex:

* **Latitude**: `17.5947`  
* **Longitude**: `78.1230`  
* **Allowed Radius**: `300 meters`

When a student clicks **Request Location Check**, the browser requests GPS access. If the calculated distance is less than or equal to 300 meters, location status becomes `verified_onsite`, unlocking court claiming and status modification actions.

## **Application Workflows**

### **Student Workflow**

1. **View Status**: Filter facilities by sport to check live vacancy and wait times.  
2. **Verify GPS**: Request browser location permission to verify presence at SNCC.  
3. **Join Queue**: Input Name and Roll Number, select the sport and court, and join the queue.  
4. **Manage Queue**: View queue placement or leave the queue at any time via the active spot banner.

### **Staff Workflow**

1. Navigate to the **Staff Portal** tab.  
2. Enter a Staff ID/PIN (e.g., `1234`, `admin`, `STAFF01`).  
3. Select the target facility and apply state changes (`EMPTY`, `FULL`, `MAINTENANCE`, etc.).  
4. Use **Admit Next Student in Queue** to clear the top waiting student and set the court status to `FULL`.

**Tkinter and Python based Desktop Application**

A desktop management application for the Sports and Cultural Centre (SNCC) badminton courts at IIT Hyderabad. Built with Python, Tkinter, and SQLite3, the application provides real-time court tracking, student queue handling, and staff access control.

## **Features**

### **Student View**

* **Court Availability Monitoring**: View live status across Courts 1 to 4 (EMPTY, FULL, MAINTENANCE, OFFICIAL MATCH, NSO Practice, Inter-IIT Practice).  
* **Queue Tracking**: View positions, names, roll numbers, and target court assignments for all students in line.  
* **Queue Registration**: Self-service form allowing students to enter their Name, Roll Number, and target court to join the queue.  
* **Manual Refresh**: On-demand synchronization with the SQLite database.

### **Staff Portal**

* **Staff Authentication**: Validates staff identification numbers against pre-seeded database records.  
* **Status Override**: Allows staff to set court status manually (e.g., mark court for Maintenance or Official Matches).  
* **Queue Admission**: Automatically admits the next waiting student in line for a specified court, sets the court state to `FULL`, and pops up an assignment confirmation.
